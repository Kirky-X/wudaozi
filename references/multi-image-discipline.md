# Multi-Image Discipline — 批量/多图出图流程纪律

> 一次任务要产出**多张**图（App 多屏概念图、网页分节参考图、成套 SKU 图、分镜连续帧）时的流程纪律。单张出图不需要本文档；美学反模式（AI 味、配色、排版）不在本文——设计侧由 maliang 承载，本文只管**数量、一致性与重生成**的行为规则。
>
> 思想内化自外部 skill imagegen-frontend-mobile 与 imagegen-frontend-web（两源 license 未考，故全部措辞为本仓库自著）；本篇是 wudaozi 侧批量出图纪律的规范文本单点，maliang explore 的「文生图方向板」轻量档引用本文。

## 触发词条

用户要「多个屏幕 / 一套 App 界面 / landing 每节一张 / 整站参考图 / 一套 N 张」→ 本文与 `prompt-template.md` 7 维公式配合使用：第一张按 7 维精写，后续张在锁定的 design bible 下做受控变化。

## 数量纪律 — 不偷懒

- 用户要几张就出几张：1 屏 → 1 张；5 屏 → 5 张。为省事压缩张数 = 弱化交付，禁止。
- 网页分节参考图：**一节一张独立横图**，禁止把多节塞进一张长图、禁止只交「最好的一张」。节不清时按高标准默认：landing/产品页/作品集 → 6 张；整站/营销站 → 8 张。
- 流程类需求（onboarding/auth/支付流）按状态拆图，不出「概念拼板」。宁要多张干净可读的图，不要一张文字缩到不可读的大拼盘。
- 每张逐张标注 `Section X of N: <名称>` 或 `Screen X of N`，一次交付完整集合。

## Design Bible — 先锁后画

多图任务在第一张前先在内部锁定设计圣经，后续每张**复述引用**而不是重新发明：平台模式与画幅、设备框样式与比例、色板逻辑、字体气质与字阶节奏、间距系统、圆角语言、图标与插画语言、纹理强度、导航模型、卡片/按钮/阴影语言。

- 变化只允许发生在：每张的构图锚点、背景模式、信息密度、次要视觉瞬间。
- 禁止跨张漂移：第 3 张开始换字体、换色温、换圆角 = 换了个产品。读者翻完全部图，必须认出是**同一个品牌世界**。

## 重生成 — 禁止裁剪旧图

某屏或某细节需要专门视图时，禁止从已有大图裁剪/放大凑数（裁剪会扭曲间距、比例与字号）。正确做法：保持同一 design bible，**重新生成**一张独立图，并按该图的用途优化可读性。发现漏图或数量不对 → 补生成缺失的，不以「已有类似的」交差。

## 生成前自查（多图任务追加项）

- [ ] 张数 = 需求张数（节/屏一一对应，不少出）？
- [ ] design bible 锁定且每张可追溯？
- [ ] 每张标注 X of N？横竖画幅与用途匹配？
- [ ] 跨张只有受控变化，品牌世界无漂移？
- [ ] 每张独立可读（无缩到不可读的拼盘）？
- [ ] 需要细节视图处是重生成而非裁剪？
- [ ] 首张是否条件反射地走了默认构图（应按内容选锚点）？
